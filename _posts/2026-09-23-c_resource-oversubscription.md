# AHV CPU and Memory overheads
One question I've heard recently is how to calculate how much overhead AHV adds on VMs - both from a CPU and Memory perspective.  Memory is perhaps the easier one to answer. There are a set of overheads that all hypervisors (in fact all operating systems) incur such as to set up the page tables to access memory, then there's the memory needed to run AHV, and potentially some additional optional services. There are also per-VM overheads which depend on the number and type of virtual devices, but the number of factors that go into the precise VM overhead is much larger. Thankfully the VM overheads are often very small (of the order of 50MB per VM) and so while these overheads do add up, it might only be seen on hosts with large numbers of VMs.

The Nutanix portal documentation page on [Memory overhead calculation](https://portal.nutanix.com/page/solution/BP-2029-AHV:nutanix-ahv-resource-oversubscription.html) is a great place to understand the host-level overheads, including a formula for calculating the rough amount of memory AHV needs before running VMs. As for the VM overheads? NCI 7.6 added a whole set of new metrics - [Advanced AHV Infrastructure Metrics](https://www.nutanix.com/tech-center/blog/smart-insights-with-advanced-ahv-intrastructure-metrics) - which include details of the host and VM overheads as well as showing exactly where things like memory overcommit and HA reservations are working in the system.

CPU is quite a bit more complicated, and I posted a [blog on that](https://www.nutanix.com/tech-center/blog/understanding-cpu-resource-management-in-nutanix-ahv) too. In summary, the overheads of AHV itself from a CPU perspective are entirely dependent on the workload running in the VMs, so it's really difficult to predict CPU usage without details of the workload. There are some recommendations in the blog, notably to use [Sizer](https://www.nutanix.com/products/sizer) to look at existing workloads and calculate the expected overheads and remaining capacity on a new system, or to use [capacity planning](https://portal.nutanix.com/page/documents/details?targetId=Intelligent-Operations-Guide-vpc_7_3:mul-capacity-planning-pc-c.html) on existing infrastructure
